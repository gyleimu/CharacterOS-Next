# Architecture decision records

**Status: RESERVED / PROSPECTIVE ONLY**

This directory is the prospective home for Architecture Decision Records
(ADRs). No retrospective ADR record exists for decisions made before the
repository-governance realignment, and historical decisions must not be
reconstructed as if they had contemporaneous ADRs.

Create an ADR when a new architecture choice needs durable rationale and
trade-off documentation, especially when it affects multiple packages,
interfaces, authority boundaries, persistence, or operational constraints.
Name records `NNNN-short-kebab-title.md` and give each one a status of
`PROPOSED`, `ACCEPTED`, `SUPERSEDED`, or `REJECTED`.

ADRs may refine choices allowed by `ARCHITECTURE.md` and the applicable formal
architecture contracts; they may not override those authorities. Frozen
experiment evidence may be cited as input but must remain unchanged. An ADR
must identify its context, decision, consequences, governing contracts, and
evidence references.
